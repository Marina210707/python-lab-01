# Лабораторна робота 2: Інвертований індекс

## Опис проєкту
Реалізовано побудову інвертованого індексу для колекції текстових документів. 
Проєкт підтримує:
- Побудову індексу за один прохід (термін → відсортований список постингів).
- Використання `dataclass` з `__slots__` для економії пам'яті.
- Булевий пошук (AND, OR, NOT) двома алгоритмами: через злиття (merge) та через множини (set).
- Серіалізацію та десеріалізацію у формати `pickle` та `json`.
- CLI-інтерфейс для побудови та пошуку.

## Порівняння використання пам'яті
Під час тестування створювалося 100 000 об'єктів `Posting`. Результати заміру через `tracemalloc`:

| Тип класу | Використана пам'ять (MB) |
| :--- | :--- |
| Звичайний клас (без `__slots__`) | 18.80 MB |
| Клас з `__slots__` | **8.40 MB** |

**Висновок:** Використання `__slots__` дозволило зменшити споживання пам'яті майже вдвічі, оскільки забрано словник `__dict__` для кожного екземпляра класу.

## Бенчмарк: Merge vs Set
Порівняння швидкості виконання операції `AND` для термінів з різною частотою (вимірювання в мілісекундах):

| Термін | Кількість документів | Час (Merge) | Час (Set) |
| :--- | :--- | :--- | :--- |
| 'мова' | 120 | 0.1445 ms | **0.0306 ms** |
| 'name' | 120 | 0.0597 ms | **0.0272 ms** |
| 'вісімка' | 24 | **0.0281 ms** | 0.0334 ms |
| 'англомовні' | 24 | 0.0302 ms | **0.0150 ms** |

**Висновок:** Алгоритм `set` (множини) виявився швидшим на великих списках документів, оскільки хеш-таблиці мають складність O(1) для перевірки наявності елемента. Алгоритм `merge` (злиття) показує хороші результати на малих списках, але поступається на великих обсягах.

## Бенчмарк: Серіалізація (Save / Load)
Збереження та завантаження індексу в різних форматах:

- **Pickle:** Розмір: 7.26 MB | Час збереження: 0.6008 с | Час завантаження: 0.6798 с
- **JSON:** Розмір: 35.56 MB | Час збереження: 8.7705 с | Час завантаження: 4.6207 с

**Висновок:** Pickle працює значно швидше і створює файли меншого розміру, оскільки зберігає об'єкти в бінарному форматі. Однак JSON є безпечнішим та людиночитабельним, що полегшує дебаг.

## Reflection (Відповіді на питання)
1. **Чому завантаження чужого pickle-файлу є небезпечним?**
   `pickle` під час завантаження може виконувати довільний код (через метод `__reduce__`). Якщо завантажити шкідливий файл, зловмисник може виконати команди на вашому комп'ютері (наприклад, видалити файли або вкрасти паролі). JSON є безпечною альтернативою, оскільки він лише парсить дані.
2. **Чому `__slots__` економить пам'ять?**
   Звичайні класи Python зберігають атрибути у спеціальному словнику `__dict__`. Словники мають великий оверхед (накладні витрати) на зберігання ключів. `__slots__` створює фіксований масив для атрибутів, що значно зменшує розмір об'єкта в пам'яті.
3. **Чому `merge` (злиття списків) ефективніший за множини на великих обсягах, і навпаки?**
   Насправді, на великих обсягах `set` часто швидший завдяки хешуванню. Але `merge` є надзвичайно ефективним, коли списки вже відсортовані і ми просто йдемо по них двома вказівниками (складність O(N+M)). Для множин потрібно спочатку створити хеш-таблицю (O(N)), що може бути повільніше на дуже великих обсягах, ніж просте злиття.
