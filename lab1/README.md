# Лабораторна робота №1: Ітератори та корпус текстів

## Опис
Мета роботи — дослідити різницю у споживанні пам'яті між потоковою обробкою даних (через генератори) та завантаженням усього корпусу в оперативну пам'ять (через списки).

## Використані технології
* Python 3.9
* Бібліотеки: `tracemalloc`, `time`, `re`, `unicodedata`, `collections.Counter`
* Середовище: PyCharm

## Результати вимірювань
Корпус складається зі 120 текстових документів (загальний обсяг ~50 МБ).

| Метод обробки | Кількість токенів | Час виконання | Пікова пам'ять |
| :--- | :--- | :--- | :--- |
| **Генератор (потоковий)** | 2 067 936 | 3.30 сек | **12.26 МБ** |
| **Список (жадібний)** | 2 067 936 | 2.97 сек | **40.51 МБ** |

## Висновок (куди пішла пам'ять)
У "жадібній" версії програма спочатку завантажує весь текст усіх 120 документів у великий список `all_texts` в оперативній пам'яті. Через це пікова пам'ять зростає до 40.51 МБ, оскільки в RAM одночасно зберігаються всі рядки. 

У версії з генератором (`iter_documents`) текст читається по одному файлу, обробляється і потім видаляється з пам'яті збирачем сміття. Завдяки цьому пікова пам'ять залишається на рівні 12.26 МБ, незалежно від того, скільки всього файлів у папці. Генератор виявився трохи повільнішим через постійне звернення до диска, але це компенсується значною економією пам'яті.
