'''Python''' (найчастіше вживане прочитання&nbsp;— «'''Па́йтон'''», запозичено назву<ref>{{Cite web |url=http://www.python.org/doc/essays/foreword/ |title=Архівована копія |accessdate=28 серпня 2008 |archive-date=6 січня 2018 |archive-url=https://web.archive.org/web/20180106000102/https://www.python.org/doc/essays/foreword/ }}</ref> з британського шоу [[Монті Пайтон]])&nbsp;— [[Інтерпретована мова програмування|інтерпретована]] [[об'єктно-орієнтоване програмування|об'єктно-орієнтована]] [[мова програмування]] високого рівня із [[строга типізація|суворою]] [[динамічна типізація|динамічною типізацією]]<ref>Guido van Rossum, ''Python Reference Manual'', release 2.4.4, 18 October 2006</ref>. Розроблена на початку [[1990|1990-х]] років [[Гвідо ван Россум]]ом. [[Структури даних]] високого рівня разом із динамічною семантикою та динамічним зв'язуванням роблять її привабливою для швидкої розробки програм, а також як засіб поєднування наявних компонентів. Python підтримує [[модуль (програмування)|модулі]] та пакети модулів, що сприяє модульності та повторному використанню коду. Інтерпретатор Python та стандартні бібліотеки доступні як у скомпільованій, так і у вихідній формі на всіх основних платформах. В мові програмування Python підтримується кілька [[Парадигма програмування|парадигм програмування]], зокрема: [[Об'єктно-орієнтоване програмування|об'єктно-орієнтована]], [[Процедурне програмування|процедурна]], [[Аспектно-орієнтоване програмування|аспектно-орієнтована]] та [[Функціональне програмування|функціональна]].

== Переваги ==
Серед основних її переваг можна назвати такі:
* чистий [[синтаксис]] (для виділення блоків слід використовувати відступи);
* переносність програм (що властиве більшості інтерпретованих мов);
* стандартний [[дистрибутив]] має велику кількість корисних модулів (включно з модулем для розробки графічного інтерфейсу);
* можливість використання Python в діалоговому режимі (дуже корисне для експериментування та розв'язання простих задач);
* стандартний дистрибутив має просте, але разом із тим досить потужне [[Інтегроване середовище розробки|середовище розробки]], яке називається [[IDLE]] і яке написане мовою Python;
* зручний для розв'язання математичних проблем (має засоби роботи з [[комплексні числа|комплексними числами]], може оперувати з цілими числами довільної величини, у діалоговому режимі може використовуватися як потужний [[калькулятор]]);
* відкритий код (можливість редагувати його іншими користувачами).

Python має ефективні [[структури даних]] високого рівня та простий, але ефективний підхід до [[Об'єктно-орієнтоване програмування|об'єктно-орієнтованого програмування]]. Елегантний синтаксис Python, динамічна обробка типів, а також те, що це [[інтерпретована мова]], роблять її ідеальною для написання скриптів та швидкої розробки прикладних програм у багатьох галузях на більшості платформ.

Інтерпретатор мови Python і багата [[Стандартна бібліотека]] (як вихідні тексти, так і бінарні дистрибутиви для всіх основних [[Операційна система|операційних систем]]) можуть бути отримані з сайту Python [http://www.python.org/ www.python.org] {{Webarchive|url=https://web.archive.org/web/20180417023815/https://www.python.org/ |date=17 квітня 2018 }}, і можуть вільно розповсюджуватися. Цей самий сайт має дистрибутиви та посилання на численні модулі, програми, утиліти та додаткову документацію.

Інтерпретатор мови Python може бути розширений функціями та типами даних, розробленими на [[C (мова програмування)|C]] чи [[Сі-плюс-плюс|C＋＋]] (або на іншій мові, яку можна викликати із C). Python також зручна як мова розширення для прикладних програм, що потребують подальшого налагодження.

== Історія ==
[[Файл:Guido_van_Rossum_OSCON_2006.jpg|thumb|[[Гвідо ван Россум]], автор Python]]
Розробка мови Python була розпочата в кінці [[1980-ті|1980-х років]]<ref>{{Cite web |url=http://www.artima.com/intv/pythonP.html |title=The Making of Python |accessdate=4 липня 2010 |archive-date=1 вересня 2016 |archive-url=https://web.archive.org/web/20160901183332/http://www.artima.com/intv/pythonP.html }}</ref> співробітником [[Centrum Wiskunde & Informatica|голландського інституту CWI]] [[Гвідо ван Россум]]ом. Для розподіленої ОС [[Amoeba (операційна система)|Amoeba]] потрібна була розширювана [[скриптова мова]], і Гвідо почав писати Python на дозвіллі, запозичивши деякі напрацювання для мови [[ABC (мова програмування)|ABC]] (Гвідо брав участь у розробці цієї мови, орієнтованої на навчання програмування). У лютому [[1991]] року Гвідо опублікував вихідний текст в [[Група новин|групі новин]] alt.sources<ref>{{Cite web |url=http://svn.python.org/view/*checkout*/python/trunk/Misc/HISTORY |title=Архівована копія |accessdate=4 липня 2010 |archiveurl=https://web.archive.org/web/20160217132249/http://svn.python.org/view/*checkout*/python/trunk/Misc/HISTORY |archivedate=17 лютого 2016 |deadurl=yes }}</ref>. Мова почала вільно поширюватися через [[Інтернет]] і сподобалася іншим [[програміст]]ам. З [[1991]] року Python є цілком [[Об'єктно-орієнтоване програмування|об'єктно-орієнтованим]]. Python також запозичив багато рис таких мов, як [[C (мова програмування)|C]], [[C++]], {{нп|Modula-3}} і {{нп|Icon (мова програмування)|Icon||Icon (programming language)}}, й окремі риси [[Функціональне програмування|функціонального програмування]] з [[Лісп]]у.

[[Файл:Python-icon.png|thumb|left|.py]]
Назва мови виникла зовсім не від [[пітони|виду плазунів]]. Автор назвав мову на честь популярного британського комедійного серіалу 70-х років [[Монті Пайтон|«Повітряний цирк Монті Пайтона»]]. Втім, все одно назву мови частіше асоціюють саме зі змією, ніж з фільмом&nbsp;— [[піктограма|піктограми]] файлів в [[KDE]] або в [[Windows]], і навіть емблема на сайті python.org зображують зміїну голову.

Наявність дружньої спільноти користувачів, поряд з дизайнерською інтуїцією Гвідо, вважається одним з головних факторів успіху Python. Розвиток мови відбувається згідно з чітко регламентованими процесами створення, обговорення, відбору та реалізації документів PEP (Python Enhancement Proposal)&nbsp;— пропозицій щодо розвитку Python<ref>{{Cite web |url=http://www.python.org/dev/peps/ |title=Index of Python Enhancement Proposals (PEPs) |accessdate=4 липня 2010 |archive-date=28 січня 2007 |archive-url=https://web.archive.org/web/20070128214511/http://www.python.org/dev/peps/ }}</ref>.

[[3 грудня]] [[2008]] року<ref>{{Cite web |url=http://python.org/download/releases/3.0/ |title=Python 3.0 Release |accessdate=4 липня 2010 |archive-date=2 червня 2009 |archive-url=https://web.archive.org/web/20090602015124/http://www.python.org/download/releases/3.0/ }}</ref>, після тривалого тестування, вийшла перша версія Python 3000 (або Python 3.0, також використовується [[Абревіатура|скорочена]] Py3k). У Python 3000 усунено багато недоліків архітектури з максимально можливим (але не повним) збереженням сумісності зі старішими версіями. На сьогодні підтримуються Python версії 3.

У 2023 році, найпопулярнішою мовою програмування серед IT-спеціалістів згідно рейтингу [[IEEE Spectrum]] стала Python. Рейтинг 2023 року охоплював 59 мов програмування<ref>[https://speka.media/ieee-spectrum-opublikuvala-reiting-naipopulyarnisix-mov-programuvannya-2023-roku-pn3l49 IEEE Spectrum опублікувала рейтинг найпопулярніших мов програмування 2023 року. // Автор: Артем Житкевич. 30.08.2023]</ref>.

== Вплив інших мов на Python ==
З'явившись порівняно пізно, Python створювався під впливом багатьох мов програмування:
* [[ABC (мова програмування)|ABC]]&nbsp;— відступи (поля) для групування операторів, високорівневі структури даних (map)<ref name="foreword">{{Cite web |url=http://www.python.org/doc/essays/foreword/ |title=Foreword for «Programming Python» (1st ed.) |accessdate=28 серпня 2008 |archive-date=6 січня 2018 |archive-url=https://web.archive.org/web/20180106000102/https://www.python.org/doc/essays/foreword/ }}</ref><ref>{{Cite web |url=http://www.artima.com/intv/python2.html |title=The Making of Python |accessdate=4 липня 2010 |archive-date=6 червня 2017 |archive-url=https://web.archive.org/web/20170606003042/http://www.artima.com/intv/python2.html }}</ref> (фактично, Python створювався як спроба виправити помилки, допущені при проєктуванні ABC);
* {{нп|Modula-3}}&nbsp;— пакети, модулі, використання <code>else</code> спільно з <code>try</code> та <code>except</code>, іменовані аргументи функцій (на це також вплинув [[Common Lisp]]);
* [[Сі (мова програмування)|С]], [[C++]]&nbsp;— деякі синтаксичні конструкції (як пише сам [[Гвідо ван Россум]]&nbsp;— він використовував найбільш несуперечливі конструкції з С, щоб не викликати неприязнь у Сі-програмістів до Python<ref name="foreword" />);
* [[Smalltalk]]&nbsp;— об'єктно-орієнтоване програмування;
* [[Lisp]]&nbsp;— окремі риси [[функціональне програмування|функціонального програмування]] (<code lang="python">lambda, map, reduce, filter</code> та інші);
* [[Fortran]]&nbsp;— зрізи масивів, комплексна арифметика;
* {{нп|Міранда (мова програмування)|Miranda||Miranda (programming language)}}&nbsp;— спискові вирази;
* [[Java]]&nbsp;— модулі logging, unittest, threading (частина можливостей оригінального модуля не реалізована), xml.sax стандартної бібліотеки, спільне використання finally та except при обробці винятків, використання @ для декораторів;
* {{нп|Icon (мова програмування)|Icon||Icon (programming language)}}&nbsp;— [[Python#Генератори|генератори]].
* [[TypeScript]]&nbsp;— ідея синтаксису підказок типів ([https://peps.python.org/pep-0484/ type hinting]). З версії Python 3.10 система підказок типів стала унікальною, «злившись» з мовою в одне ціле. До того ж у Python підказки типів ніяк не впливають на роботу інтерпретатора.

Більша частина інших можливостей Python (наприклад, байт-компіляція [[Початковий код|вихідного коду]]) також була реалізована раніше в інших мовах.

== Портованість ==
Python [[Портування|портованна]] і працює майже на всіх відомих платформах&nbsp;— від [[Кишеньковий персональний комп'ютер|КПК]] до [[мейнфрейм]]ів. Існують порти під [[Microsoft Windows]], всі варіанти [[UNIX]] (включаючи [[FreeBSD]] та [[GNU/Linux]]), [[Plan 9]], [[Mac OS]] та [[Mac OS X]], [[iPhone OS]] 2.0 і вище, [[Palm OS]], [[OS/2]], [[Amiga]], [[IBM System i|AS/400]] та навіть {{нп|OS/390}}, [[Symbian]] та [[Android]]<ref>{{cite web|url=http://www.damonkohler.com/2008/12/python-on-android.html|title=Python on Android|publisher=www.damonkohler.com|accessdate=2009-12-19|language=англійською|archiveurl=https://www.webcitation.org/5w4n0S15k?url=http://www.damonkohler.com/2008/12/python-on-android.html|archivedate=2011-01-28|deadurl=no}}</ref>.

У міру старіння платформи її підтримка в основній гілці мови припиняється. Наприклад, з версії 2.6 припинена підтримка [[Windows 95]], [[Windows 98]] та [[Windows ME]].<ref>{{cite web|url=http://docs.python.org/whatsnew/2.6.html#port-specific-changes-windows|title=Port-Specific Changes: Windows|work=Python v2.6.1 documentation. What's New in Python 2.6|publisher=Python Software Foundation|accessdate=2008-12-11|language=англійською|archiveurl=https://www.webcitation.org/5w4n1Glim?url=http://docs.python.org/whatsnew/2.6.html#port-specific-changes-windows#port-specific-changes-windows|archivedate=2011-01-28|deadurl=no}}</ref> Однак на цих платформах можна використовувати попередні версії Python&nbsp;— спільнота активно підтримує версії Python починаючи від 2.3 (для них виходять виправлення).

При цьому, на відміну від багатьох портованих систем, для всіх основних платформ Python має підтримку характерних для даної платформи технологій (наприклад, Microsoft [[Microsoft Component Object Model|COM]]/[[Microsoft Distributed Component Object Model|DCOM]]). Навіть більше, існує спеціальна версія Python для [[Віртуальна машина Java|віртуальної машини Java]]&nbsp;— [[Jython]], що дозволяє інтерпретатору виконуватися на будь-якій системі, яка підтримує Java, при цьому класи Java можуть безпосередньо використовуватися з Python й навіть бути написаними на ньому. Також кілька проєктів забезпечують інтеграцію з платформою [[Microsoft.NET]], основні з яких&nbsp;— [[IronPython]] та [[Python.Net]].

== Типи й структури даних ==
[[Файл:Python 3. The standard type hierarchy.png|thumb]]
Python підтримує [[система типізації|динамічну типізацію]], тобто, тип змінної визначається лише під час виконання. З базових типів слід зазначити підтримку цілих чисел довільної довжини і [[комплексні числа|комплексних чисел]]. Python має багату бібліотеку для роботи з [[рядок (структура даних)|рядками]], зокрема, кодованими в [[юнікод]]і.

З колекцій Python підтримує [[кортеж]]і (''tuples''), [[Список (абстрактний тип даних)|списки]] ([[Масив (структура даних)|масиви]]), [[Словник (структура даних)|словники (асоціативні масиви)]] і від версії 2.4, [[Множина (структура даних)|множини]].

Система класів підтримує [[множинне успадкування]] і [[метапрограмування]]. Будь-який тип, включаючи базові, входить до системи [[клас (програмування)|класів]], й за необхідності можливе успадкування навіть від базових типів.

== Можливості ==

=== Інтерактивний режим ===
Подібно [[Лісп]]у та [[Пролог (мова програмування)|Прологу]] в режимі відлагодження, інтерпретатор Python має інтерактивний режим роботи, при якому введені з клавіатури вирази відразу ж виконуються, а результат виводиться на екран. Цей режим цікавий не тільки новачкам, але й досвідченим програмістам, які можуть протестувати в інтерактивному режимі будь-який фрагмент коду, перш ніж використовувати його в основній програмі, або просто використовувати як [[калькулятор]] з великим набором функцій.

Діалог роботи з Python в інтерактивному режимі має такий вигляд:
<syntaxhighlight lang="python">
>>> 2 ** 100 # піднесення 2 до 100-го степеня
1267650600228229401496703205376L
>>> from math import * # імпорт математичних функцій
>>> sin (pi * 0.5) # обчислення синуса від половини пі
1.0
>>> help (sorted) # допомогу по функції sorted
Help on built-in function sorted in module __builtin__:
sorted (…)
   sorted (iterable, cmp=none, key=none, reverse=false) -> new sorted list
</syntaxhighlight>
В інтерактивному режимі доступний [[дебагер]] <tt>pdb</tt> та система довідки (викликається за <code>help()</code>). Система допомоги працює для модулів, класів і функцій, тільки якщо ті були забезпечені рядками документації.

Крім вбудованої, існує й покращена інтерактивна оболонка [[IPython]]<ref>{{Cite web |url=http://ipython.scipy.org/ |title=IPython |accessdate=20 червня 2019 |archiveurl=https://web.archive.org/web/20180804135112/http://ipython.scipy.org/ |archivedate=4 серпня 2018 |deadurl=yes }}</ref>.

=== Підтримувані парадигми програмування ===
Пайтон підтримує такі парадигми програмування:

* процедурне програмування
* об'єктно орієнтоване програмування
* функціональне програмування.

При цьому на 100 відсотків підтримується тільки процедурне програмування. Є деякі послаблення деяких аспектах ООП - наприклад інкапсуляція даних не повна. Що стосується функціонального програмування, то можна казати про значну підтримку цієї парадигми.

==== Процедурне програмування ====
На відміну від інших мов, що підтримують ООП, Python не вимагає програмувати виключно створюючи класи. В ньому можна створювати код в чистому процедурному стилі із розробкою 'згори-вниз'. Ви можете створити повноцінний проєкт, не створивши жодного свого класу.

==== Об'єктно-орієнтоване програмування ====
Дизайн мови Python побудований навколо об'єктно-орієнтованої моделі програмування. Реалізація [[Об'єктно-орієнтоване програмування|ООП]] в Python є елегантною, потужною та добре продуманою, але разом з тим, достатньо специфічною в порівнянні з іншими [[Об'єктно-орієнтована мова програмування|об'єктно-орієнтованими мовами]].

Можливості та особливості:
# Класи є одночасно об'єктами з усіма нижче наведеними можливостями.
# Успадкування, в тому числі множинне.
# Поліморфізм (всі функції віртуальні).
# Інкапсуляція (два рівні&nbsp;— загальнодоступні та приховані методи і поля). Особливість&nbsp;— приховані члени доступні для використання та помічені як приховані лише особливими іменами.
# Спеціальні методи, що керують життєвим циклом об'єкта: конструктори, деструктори, розподільники пам'яті.
# Перевантаження операторів (усіх, крім <code>is, '.', '='</code> і символьних логічних).
# Властивості (імітація поля за допомогою функцій).
# Управління доступу до полів (емуляція полів і методів, частковий доступ тощо).
# Методи для управління найпоширенішими операціями (істиннісне значення, <code>len()</code>, глибоке копіювання, [[серіалізація]], ітерація по об'єкту, …)
# Метапрограмування (управління створенням класів, тригери на створення класів, та ін)
# Повна [[Інтроспекція (програмування)|інтроспекція]].
# Класові та статичні методи, класові поля.
# Класи, вкладені у функції та інші класи.

==== Функціональне програмування ====
Python в значній мірі підтримує парадигму [[функціональне програмування|функціонального програмування]], зокрема:
* функція є об'єктом;
* функції вищих порядків;
* рекурсія;
* розвинена обробка списків (спискові вирази, операції над послідовностями, ітератори);
* аналог замикань (closures);
* часткове застосування функції;
* можливість реалізації інших засобів на самій мові (наприклад, [[каррінг]]).

=== Модулі та пакети ===
[[Програмне забезпечення]] ([[застосунок]] або [[бібліотека (програмування)|бібліотека]]) на Python оформлюється у вигляді [[Модуль (програмування)|модулів]], які у свою чергу можуть бути зібрані в ''пакунки''. Модулі можуть розташовуватися як у [[Каталог (файлова система)|каталогах]], так і в [[ZIP|ZIP-архівах]]. Модулі можуть бути двох типів за своїм походженням: модулі, написані на «чистому» Python, і модулі розширення (extension modules), написані на інших мовах програмування. Наприклад, у стандартній бібліотеці є «чистий» модуль pickle і його аналог на Сі: cPickle. Модуль оформляється у вигляді окремого файлу, а пакет&nbsp;— у вигляді окремого каталогу. Підключення модуля до програми здійснюється оператором <code>import</code>. Після імпорту модуль представлений окремим об'єктом, що дає доступ до [[простір імен|простору імен]] модуля. У ході виконання програми модуль можна перезавантажити функцією <code>reload()</code>.

=== Інтроспекція ===
Python підтримує повну [[Інтроспекція (програмування)|інтроспекцію]] часу виконання. Це означає, що для будь-якого об'єкта можна отримати всю інформацію про його внутрішню структуру.

Застосування інтроспекції ([[метапрограмування]]) є важливою частиною того, що називають «pythonic style», і широко застосовується в бібліотеках і [[фреймворк]]ах Python, таких як [[Python Remote Objects|PyRO]], {{нп|Pyro|||Python Robotics}}, [[PLY]], [[CherryPy]], [[Django]] та інших, заощаджуючи час програміста, що ними користується.

=== Обробка винятків ===
[[Обробка винятків]] підтримується в Python допомогою операторів <code> try, except, else, finally, raise</code>, що утворюють блок обробки винятків. У загальному випадку блок має такий вигляд:
<syntaxhighlight lang="python">
try:
    # Тут код, в якому може виникнути виняткова ситуація
    raise ExceptionType ("message")
except (Тип винятку1, Тип винятку2, …), Змінна:
    # Код в блоці виконується, якщо тип винятку збігається з одним з типів
    # (Тип винятку1, Тип винятку2, ...) або є спадкоємцем одного
    # з цих типів.
    # Отриманий виняток доступний в необов'язковій Змінній.
except (Тип винятку3, Тип винятку4, …), Змінна:
    # Кількість блоків except не обмежено
    raise # Згенерувати виняток "поверх" отриманого; без параметрів — повторно згенерувати отримане
except:
    # Буде виконано за будь-якого винятку, не обробленого типізованими блоками except
else:
    # Код блоку виконується, якщо не було отримано винятків.
finally:
    # Буде виконано в будь-якому випадку, можливо після відповідного
    # блоку except або else
</syntaxhighlight>
Спільне використання <code>else, except</code> і <code>finally</code> стало можливо тільки починаючи з Python 2.5. Інформація про поточний виняток завжди доступна через <code>sys.exc_info()</code>. Крім значення винятку, Python також зберігає стан стеку аж до точки збудження винятку&nbsp;— так званий traceback.

На відміну від мов програмування, що компілюються, в Python використання винятку не призводить до значних накладних витрат (а часто навіть дозволяє прискорити виконання програм) і дуже широко використовується. Винятки узгоджуються з філософією Python (10-й пункт [[#Філософія|«дзену Python»]]&nbsp;— «Помилки ніколи не повинні ігноруватися») та є одним із засобів підтримки «[[Качина типізація|качиної типізації]]».

Іноді, замість явної обробки винятків, зручніше використовувати блок [[Python#Керування контекстом виконання|<code>with</code>]] (доступний, починаючи з Python 2.5).

=== Ітератори ===
У програмах на Python широко використовуються [[ітератор]]и. Цикл <code>for</code> може працювати як з послідовністю, так і з ітераторами. Усі колекції, як правило, надають ітератор. Об'єкти визначеного користувачем класу теж можуть бути ітераторами. Модуль <code>itertools</code> стандартної бібліотеки містить багато корисних функцій для роботи з ітераторами. На відміну від звичайних послідовностей, всі елементи яких зберігаються в пам'яті, отримання наступного елемента забезпечує генератор&nbsp;— спеціальна функція, звернення до якої обчислює і повертає наступний елемент генератора.

=== Генератори ===
Однією з цікавих можливостей мови є '''генератори'''&nbsp;— функції, що між викликами зберігають внутрішній стан: значення локальних змінних і поточну інструкцію (див. також: [[співпрограма]]). Генератори можуть використовуватися як [[ітератор]]и для структур даних і для [[Ліниві обчислення|лінивих обчислень]]. Наприклад, генератор чисел Фібоначчі:

<syntaxhighlight lang="python">
def fib():
    a, b = 1, 1
    while True:
        yield a
        a, b = b, a + b

while x in fib():
     print(x)
</syntaxhighlight>

При виклику генератора функція негайно повертає об'єкт-ітератор, який зберігає поточну точку виконання та стан локальних змінних функції. При запиті наступного значення (за допомогою методу <code>next()</code>, який неявно викликається в циклі <code>for</code>) генератор продовжує виконання функції від попередньої точки зупину до наступного оператора <code>yield</code> або <code>return</code>.

У Python 2.4 з'явилися '''генераторні вирази'''&nbsp;— вирази, що дають у результаті генератор. Генераторні вирази дозволяють заощадити пам'ять там, де інакше потрібно було б використовувати список із проміжними результатами:
<syntaxhighlight lang="python">
>>> sum(i for i in xrange (1, 100) if i % 2 != 0)
2500
</syntaxhighlight>
У цьому прикладі підсумовуються всі непарні числа від 1 до 99.

Починаючи з версії 2.5, Python підтримує повноцінні співпроцедури: тепер в генератор можна передавати значення за допомогою методу <code>send()</code> та збуджувати в його контексті виняток за допомогою методу <code>throw()</code>.

=== Керування контекстом виконання ===
У Python 2.5 з'явилися засоби для керування контекстом виконання блоку коду&nbsp;— оператор <code>with</code> та модуль <code>contextlib</code>.

Оператор може застосовуватися в тих випадках, коли до та після деяких дій обов'язково мають виконуватися якісь інші дії, незалежно від створених у блоці винятків або операторів <code>return</code>: файли має бути закрито, ресурси звільнено, перенаправлення стандартного введення/виведення завершено, тощо. Оператор полегшує читання коду, отже, допомагає уникати помилок.

=== Декоратори ===
Починаючи з версії 2.4, Python дозволяє використовувати, так звані, ''Декоратори''<ref>{{Cite web |url=http://www.python.org/dev/peps/pep-0318/ |title=PEP318 |accessdate=5 липня 2010 |archive-date=6 листопада 2013 |archive-url=https://web.archive.org/web/20131106174805/http://www.python.org/dev/peps/pep-0318/ }}</ref> (не слід плутати з однойменним [[Шаблони проєктування програмного забезпечення|шаблоном проєктування]]) для підтримки існуючої практики перетворення функцій та методів у місці визначення (декораторів може бути декілька). Після довгих дебатів для декораторів став використовуватися символ <code>@</code> у рядках, що передують визначенню функції або методу. Наступний приклад містить опис статичного методу без застосування декоратора:
<syntaxhighlight lang="python">
def my_wonderful_method ():
    return "Деякий метод"
my_wonderful_method = staticmethod(my_wonderful_method)
</syntaxhighlight>
і за допомогою декоратора:
<syntaxhighlight lang="python">
@staticmethod
def my_wonderful_method ():
    return "Деякий метод"
</syntaxhighlight>
Декоратор&nbsp;— це функція, першим аргументом якої є декорована функція або метод. Декоратори можна вважати елементом [[Аспектно-орієнтоване програмування|аспектно-орієнтованого програмування]].

З версії 2.6 декоратори можна використовувати з класами, аналогічно функціям.

=== Інші можливості ===
У Python є ще кілька можливостей, що відрізняють його від багатьох інших мов високою гнучкістю та динамічністю.

Наприклад, клас є об'єктом, а в операторі визначення класу можна використовувати вирази в списку батьківських класів.
<syntaxhighlight lang="python">
def getClass():
    return dict
class D(getClass()):
    pass
d = D()
</syntaxhighlight>
Можна модифікувати багато об'єктів під час виконання, наприклад класи:
<syntaxhighlight lang="python">
>>> class X(object): pass
…
>>> y = X()
>>> y.wrongMethod() # такого методу поки немає
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
AttributeError: 'X' object has no attribute 'wrongMethod'
>>> X.wrongMethod = lambda self : 'im here' # додамо його
>>> y.wrongMethod() # так як доступ до методу призводить до пошуку по __dict__ класу,
'im here' # то wrongMethod стає доступним всім екземплярам
</syntaxhighlight>

== Бібліотеки ==

=== Стандартна бібліотека ===
[[Файл:Python batteries included.jpg|thumb|Python поставляється «з батарейками в комплекті».]]

Багата стандартна [[Бібліотека (програмування)|бібліотека]] є однією з привабливостей мови Python. Тут є засоби для роботи з багатьма [[Мережний протокол|мережевими протоколами]] та форматами [[Інтернет]]у, наприклад, модулі для написання [[HTTP-сервер]]ів та клієнтів, для розбору та створення поштових повідомлень, для роботи з [[XML]], тощо. Набір модулів для роботи з [[операційна система|операційною системою]] дозволяє писати крос-платформні [[застосунки]]. Існують модулі для роботи з [[Регулярний вираз|регулярними виразами]], текстовими [[Кодування символів|кодуваннями]], [[мультимедіа|мультимедійними]] форматами, [[криптографія|криптографічними]] протоколами, архівами, [[Серіалізація|серіалізацією]] даних, [[юніт-тестування]]м та ін.

=== Модулі розширення та програмні інтерфейси ===
Крім стандартної бібліотеки існує багато інших, що надають інтерфейс до всіх системних викликів на різних платформах; зокрема, на платформі [[Win32]] підтримуються всі виклики [[Windows API|Win32 API]], а також [[Component Object Model|COM]] в обсязі не меншому, ніж у [[Visual Basic]] або [[Delphi (мова програмування)|Delphi]]. Існує велика кількість прикладних бібліотек для Python у різноманітних галузях: [[Вебпрограмування|веброзробка]], [[База даних|бази даних]], обробка зображень, обробка тексту, [[чисельні методи]], програми [[операційна система|операційної системи]] тощо.

Для Python прийнята специфікація програмного інтерфейсу до баз даних [[DB-API 2]] та розроблено відповідні цій специфікації пакети для доступу до різних [[СУБД]]: [[PostgreSQL]], [[Oracle (СУБД)|Oracle]], [[Sybase]], [[Firebird]] ([[Interbase]]), [[Informix]], [[Microsoft SQL Server]], [[MySQL]] та [[sqlite]]. На платформі [[Microsoft Windows]] доступ до БД можливий через [[ADO]] ([[ADOdb]]). Комерційний пакет mxODBC для доступу до СУБД через [[ODBC]] для платформ Windows і [[UNIX]] розроблений eGenix<ref>[http://egenix.com/eGenix.com — Professional Python Software, Skills and Services]{{Недоступне посилання|date=серпня 2019 |bot=InternetArchiveBot }}</ref>. Для Python написано багато [[Object-relational mapping|ORM]]: ([[SQLObject]], [[SQLAlchemy]], Dejavu, [[Django]]), виконані програмні каркаси для розробки [[вебзастосунок|вебзастосунків]] ([[Django]], [[Pylons]]).

Бібліотека [[NumPy]] для роботи з багатовимірними [[Масив (структура даних)|масивами]] дозволяє досягти продуктивності наукових розрахунків, порівнянної зі спеціалізованими пакетами. [[SciPy]] використовує NumPy і надає доступ до великого спектра математичних алгоритмів (матрична алгебра&nbsp;— [[BLAS]], level 1-3 і [[LAPACK]]; [[ШПФ]]).

Бібліотека [[WSGI]]<ref>{{Cite web |url=http://www.python.org/dev/peps/pep-0333/ |title=PEP333 |accessdate=5 липня 2010 |archive-date=9 червня 2021 |archive-url=https://web.archive.org/web/20210609072317/https://www.python.org/dev/peps/pep-0333/ }}</ref>&nbsp;— інтерфейс шлюзу з вебсервером (Python Web Server Gateway Interface).

Python надає простий і зручний програмний інтерфейс [[C API]] для написання власних модулів на мовах [[Сі (мова програмування)|С]] та [[C++]]. Інструмент [[SWIG]] дозволяє майже автоматично отримувати прив'язки для використання C/C++ бібліотек у коді на Python. Можливості цього та інших інструментів варіюються від автоматичної генерації (C/C++/Fortran)-Python інтерфейсів за спеціальними файлами ([[SWIG]], pyste<ref>{{Cite web |url=http://www.boost.org/libs/python/pyste/index.html |title=Pyste Documentation |accessdate=5 липня 2010 |archiveurl=https://web.archive.org/web/20080830030353/http://boost.org/libs/python/pyste/index.html |archivedate=30 серпня 2008 |deadurl=yes }}</ref>, SIP<ref>{{Cite web |url=http://www.riverbankcomputing.co.uk/sip/ |title=Архівована копія |accessdate=5 липня 2010 |archiveurl=https://web.archive.org/web/20080419094314/http://www.riverbankcomputing.co.uk/sip/ |archivedate=19 квітня 2008 |deadurl=yes }}</ref>, pyfort<ref>{{Cite web |url=http://pyfortran.sourceforge.net/ |title=Архівована копія |accessdate=5 липня 2010 |archive-date=8 лютого 2007 |archive-url=https://web.archive.org/web/20070208104412/http://pyfortran.sourceforge.net/ }}</ref>) до надання зручніших API ([[boost]]::python<ref>{{Cite web |url=http://www.boost.org/libs/python/doc/ |title=Boost.Python |accessdate=5 липня 2010 |archive-date=3 лютого 2007 |archive-url=https://web.archive.org/web/20070203031936/http://www.boost.org/libs/python/doc/ }}</ref>, CXX<ref>{{Cite web |url=http://cxx.sourceforge.net/ |title=PyCXX: Write Python Extensions in C |accessdate=5 липня 2010 |archive-date=3 лютого 2007 |archive-url=https://web.archive.org/web/20070203132217/http://cxx.sourceforge.net/ }}</ref> та ін.) Інструмент стандартної бібліотеки [[ctypes]] дозволяє програмам Python безпосередньо викликати функції з [[динамічна бібліотека|динамічних бібліотек]]/[[Dll|DLL]], написаних на C. Існують модулі, що дозволяють вбудовувати код на С/C++ прямо у вихідні файли Python, створюючи розширення «на льоту» (pyinline<ref>{{Cite web |url=http://pyinline.sourceforge.net/ |title=PyInline: Mix Other Languages directly Inline with your Python |accessdate=5 липня 2010 |archive-date=15 січня 2007 |archive-url=https://web.archive.org/web/20070115141930/http://pyinline.sourceforge.net/ }}</ref>, weave<ref>{{Cite web |url=http://www.scipy.org/Weave |title=Weave |accessdate=5 липня 2010 |archiveurl=https://web.archive.org/web/20100706171347/http://www.scipy.org/Weave |archivedate=6 липня 2010 |deadurl=yes }}</ref>). Для підключення математичних функцій, особливо із застосуванням [[NumPy]], наразі офіційно рекомендованим є [[Cython]]<ref name=":0">{{Cite web |url=http://www.cython.org/ |title=Cython: C-Extensions for Python |accessdate=5 липня 2010 |archive-date=11 серпня 2007 |archive-url=https://web.archive.org/web/20070811093728/http://www.cython.org/ }}</ref>.

Інший підхід полягає у вбудовуванні інтерпретатора Python у застосунки. Python легко вбудовується в програми на [[Java]], [[C (мова)|C]]/[[C++]], [[Ocaml]]. Взаємодія Python-застосунків з іншими системами можлива також за допомогою [[CORBA]], [[XML-RPC]], [[SOAP]], [[Component Object Model|COM]].

За допомогою Pyrex<ref name="pyrex">{{Cite web |url=http://www.cosc.canterbury.ac.nz/greg.ewing/python/Pyrex/ |title=Pyrex |accessdate=5 липня 2010 |archive-date=26 вересня 2018 |archive-url=https://web.archive.org/web/20180926130058/http://www.cosc.canterbury.ac.nz/greg.ewing/python/Pyrex/ }}</ref> можлива компіляція Python-подібної мови (додано можливість типізації) в еквівалентний Сі-код і зв'язування із зовнішніми модулями.

Експериментальний проєкт shed skin<ref>{{Cite web |url=http://sourceforge.net/projects/shedskin |title=Shedskin {{!}} Download Shedskin software for free at SourceForge.net |accessdate=5 липня 2010 |archive-date=11 червня 2010 |archive-url=https://web.archive.org/web/20100611025122/http://sourceforge.net/projects/shedskin/ }}</ref><ref name="shed-skin-blog">{{Cite web |url=http://shed-skin.blogspot.com/ |title=Shed Skin — An Optimizing Python-to-C++ Compiler |accessdate=5 липня 2010 |archive-date=11 серпня 2011 |archive-url=https://web.archive.org/web/20110811024224/http://shed-skin.blogspot.com/ }}</ref> передбачає створення компілятора для трансформації неявно типізованих Python програм в оптимізований С++ код. Починаючи з версії 0.22 shed skin дозволяє компілювати окремі функції в модулі розширень. Повна компіляція (станом на [[1 липня]] [[2007]]) далека від завершення.

Python та переважна більшість бібліотек до нього безкоштовні й поставляються у вихідних кодах. Навіть більше, на відміну від багатьох відкритих систем, ліцензія ніяк не обмежує використання Python у комерційних розробках та не накладає ніяких зобов'язань, крім зазначення авторських прав.

=== Графічні бібліотеки ===
З Python поставляється бібліотека [[tkinter]] на основі [[Tcl]]/[[Tk]] для створення крос-платформних програм з [[GUI|графічним інтерфейсом]].

Для науково-технічної мети найбільшого поширення набуло використання [[matplotlib]]&nbsp;— бібліотеки з інтерфейсом, аналогічним MATLAB Plot Tool.

Існують розширення, що дозволяють використовувати всі основні GUI бібліотеки&nbsp;— [[wxPython]]<ref>{{Cite web |url=http://www.wxpython.org/ |title=wxPython |accessdate=5 липня 2010 |archive-date=9 червня 2021 |archive-url=https://web.archive.org/web/20210609072244/https://www.wxpython.org/ }}</ref>, засноване на бібліотеці [[wxWidgets]], [[PyGTK]] для [[GTK+]], [[PyQt]] та [[PySide]] для [[Qt]] та інші. Деякі з них також надають широкі можливості для роботи з базами даних, графікою та мережами, використовуючи всі можливості бібліотеки, на якій базуються.

Для створення ігор та програм, що вимагають нестандартного інтерфейсу, можна використовувати бібліотеку [[Pygame]]. Вона також надає великі засоби роботи з [[мультимедіа]]: з її допомогою можна керувати звуком і зображеннями, відтворювати відео. Надаване pygame апаратне прискорення графіки [[OpenGL]] має більш високорівневий інтерфейс в порівнянні з PyOpenGL<ref>{{Cite web |url=http://pyopengl.sourceforge.net/ |title=Архівована копія |accessdate=5 липня 2010 |archive-date=15 червня 2011 |archive-url=https://web.archive.org/web/20110615075139/http://pyopengl.sourceforge.net/ }}</ref>, що копіює семантику С-бібліотеки для OpenGL. Є також PyOgr<ref>{{Cite web |url=http://www.ogre3d.org/wiki/index.php/PyOgre |title=PyOgre: Ogre Wiki |accessdate=5 липня 2010 |archiveurl=https://web.archive.org/web/20090129100116/http://www.ogre3d.org/wiki/index.php/PyOgre |archivedate=29 січня 2009 |deadurl=yes }}</ref>, що забезпечує прив'язку до [[OGRE]]&nbsp;— високорівневої об'єктно-орієнтованої бібліотеки 3D-графіки. Крім того, існує бібліотека pythonOCC<ref>{{Cite web |url=http://www.pythonocc.org/ |title=pythonOCC, 3D CAD/CAE/PLM development framework for the Python programming language |accessdate=5 липня 2010 |archive-date=8 серпня 2011 |archive-url=https://web.archive.org/web/20110808024321/http://www.pythonocc.org/ }}</ref>, що забезпечує прив'язку до середовища 3D-моделювання та симуляції OpenCascade.<ref>{{Cite web |url=http://www.opencascade.org/ |title=Open CASCADE Technology, 3D modeling & numerical simulation |accessdate=5 липня 2010 |archive-date=18 березня 2009 |archive-url=https://web.archive.org/web/20090318141312/http://www.opencascade.org/ }}</ref>.

Для роботи з [[Растрова графіка|растровою графікою]] використовується бібліотека [[Python Imaging Library]].

== Порівняння з іншими мовами ==
Найчастіше Python порівнюють з [[Perl]] та [[Ruby]]. Ці мови також є інтерпретованими та мають приблизно однакову швидкість виконання програм. Як і Perl, Python може успішно застосовуватися для написання скриптів (сценаріїв). Як і Ruby, Python є добре продуманою системою для [[Об'єктно-орієнтоване програмування|ООП]].

Засоби [[функціональне програмування|функціонального програмування]] частково запозичені з [[Scheme]] та {{нп|Icon (мова програмування)|Icon||Icon (programming language)}}.

Попри те, що Python має досить самобутній синтаксис, одним із принципів дизайну цієї мови є [[принцип найменшого подиву]].

=== Недоліки ===
Див також списки недоліків мови Python<ref>{{Cite web |url=http://zephyrfalcon.org/labs/python_pitfalls.html |title=zephyrfalcon.org::labs::10 Python pitfalls |accessdate=6 липня 2010 |archive-date=10 серпня 2013 |archive-url=https://web.archive.org/web/20130810230937/http://zephyrfalcon.org/labs/python_pitfalls.html }}</ref>.

==== Низька швидкодія ====
Python, як і багато інших [[інтерпретована мова програмування|інтерпретованих мов]], які не застосовують, наприклад, [[JIT-компіляція|JIT]]-компілятори, мають загальний недолік&nbsp;— порівняно низьку швидкість виконання програм<ref name="alioth-benchmark">{{cite web|url=http://shootout.alioth.debian.org/u32/benchmark.php?test=all&lang=python&lang2=gpp&box=1|title=Python/C++ GNU g++|work=Computer Language Benchmarks Game|publisher=???|accessdate=2009-07-01|archiveurl=https://www.webcitation.org/5w4n30Deb?url=http://shootout.alioth.debian.org/u32/benchmark.php?test=all|archivedate=2011-01-28|deadurl=yes}}</ref>. Однак, у випадку з Python цей недолік компенсується зменшенням часу розробки програми<ref name="alioth-benchmark" /> У середньому, програма, написана на Python, в 2-4 рази компактніша, ніж її аналог на [[C++]] або [[Java]]<ref name="alioth-benchmark" />. Збереження [[байт-код]]у (файли <tt>.pyc</tt> і <tt>.pyo</tt>) дозволяє інтерпретатору не витрачати зайвий час на перекомпіляцію коду модулів при кожному запуску, на відміну, наприклад, від мови [[Perl]]. Крім того, існує спеціальна JIT-бібліотека psyco<ref> [http://psyco.sf.net/ Psyco] {{ref-en}}&nbsp;— JIT-компілятор для Python, що дозволяє збільшити швидкість роботи програм в 3-10 разів </ref> (проте призводить до збільшення споживання оперативної пам'яті). Ефективність psyco значною мірою залежить від архітектури програми.

Існують проєкти реалізацій мови Python, що вводять високопродуктивні віртуальні машини (ВМ) як [[Back-end|компілятора заднього плану]]. Прикладами таких реалізацій може служити PyPy, що базується на LLVM; більш ранньою ініціативою є проєкт [[Parrot (віртуальна машина)|Parrot]]. Очікується, що використання ВМ типу LLVM призведе до тих самих результатів, що й використання аналогічних підходів для реалізацій мови Java, де низька обчислювальна продуктивність в основному подолана<ref name="unladen-swallow">{{cite web|url=http://code.google.com/p/unladen-swallow/wiki/ProjectPlan|title=unladen-swallow. A faster implementation of Python|publisher=code.google|accessdate=2009-06-22|quote=Goals: ... Produce a version of Python at least 5x faster than CPython|archiveurl=https://www.webcitation.org/5w4n3soB7?url=http://code.google.com/p/unladen-swallow/wiki/ProjectPlan|archivedate=2011-01-28|deadurl=no}}</ref>.

Низка програм/бібліотек для інтеграції з іншими мовами програмування (див. вище) надають можливість використовувати іншу мову для написання критичних ділянок.

У найпопулярнішій реалізації мови Python інтерпретатор досить великий і більш вимогливий до ресурсів, ніж в аналогічних популярних реалізаціях [[Tcl]], [[Forth]], [[LISP]] або [[Lua]], що обмежує його застосування у вбудованих системах. Тим не менше, Python знайшов застосування в [[Кишеньковий персональний комп'ютер|КПК]] і деяких моделях мобільних телефонів<ref name="PyS60">{{Cite web |url=http://wiki.opensource.nokia.com/projects/PyS60 |title=Python for S60 — OpenSource |accessdate=6 липня 2010 |archiveurl=https://web.archive.org/web/20090806081738/http://wiki.opensource.nokia.com/projects/PyS60 |archivedate=6 серпня 2009 |deadurl=yes }}</ref>.

==== Відсутність статичної типізації ====

Python є мовою з динамічною типізацією, що означає, що типи змінних визначаються під час виконання програми, а не на етапі компіляції<ref>{{Cite web|url=https://docs.python.org/3/glossary.html#term-dynamic-typing|title=Dynamic typing|publisher=Python Documentation|accessdate=28 вересня 2023}}</ref>. Це надає гнучкість при написанні коду, але може призвести до помилок, які стають видимими лише під час виконання програми, таких як AttributeError.

Починаючи з версії Python 3.5, була введена система підказок типів (type hints) через PEP 484<ref>{{Cite web|url=https://www.python.org/dev/peps/pep-0484/|title=PEP 484 – Type Hints|date=5 травня 2015|publisher=Python Software Foundation|accessdate=28 вересня 2023}}</ref>. Це дозволяє розробникам додавати анотації типів до свого коду, що може бути використано статичними аналізаторами коду (наприклад, mypy, pyright) для виявлення типових помилок до виконання програми.

Приклад використання підказок типів:

<syntaxhighlight lang="python"> def greeting(name: str) -> str: return 'Hello ' + name </syntaxhighlight>
Хоча інтерпретатор Python за замовчуванням ігнорує ці підказки під час виконання, сторонні інструменти можуть використовувати їх для статичної перевірки типів<ref>{{Cite web|url=https://docs.python.org/3/library/typing.html|title=typing — Support for type hints|publisher=Python Documentation|accessdate=28 вересня 2023}}</ref>. Крім того, стандартна бібліотека Python містить модуль typing, який надає типи для складніших структур даних, таких як List, Dict, Tuple тощо.

Введення підказок типів дозволило частково компенсувати відсутність статичної типізації, надавши можливість виявляти деякі помилки на етапі розробки. Однак це не впливає на швидкодію програм, оскільки інтерпретатор не виконує перевірку типів під час виконання<ref>{{Cite web|url=https://docs.python.org/3/library/typing.html#performance|title=Performance implications|publisher=Python Documentation|accessdate=28 вересня 2023}}</ref>.

Починаючи з Python 3.10, було введено синтаксис об'єднання типів за допомогою оператора |, що спрощує написання анотацій типів<ref>{{Cite web|url=https://www.python.org/dev/peps/pep-0604/|title=PEP 604 – Allow writing union types as X | Y|date=8 липня 2020|publisher=Python Software Foundation|accessdate=28 вересня 2023}}</ref>:

<syntaxhighlight lang="python"> def process(data: int | str) -> None: pass </syntaxhighlight>
Також існують проєкти, такі як Pyre<ref>{{Cite web|url=https://pyre-check.org/|title=Pyre – A performant type checker for Python|publisher=Meta|accessdate=28 вересня 2023}}</ref> та Pytype<ref>{{Cite web|url=https://github.com/google/pytype|title=pytype – a static type analyzer for Python code|publisher=GitHub|accessdate=28 вересня 2023}}</ref>, які надають можливості статичного аналізу типів для Python.

Відсутність статичної типізації все ще залишається характерною особливістю Python, але завдяки підказкам типів та інструментам статичного аналізу розробники можуть зменшити кількість типових помилок і покращити якість коду.

==== Неможливість модифікації вбудованих класів ====
У порівнянні з [[Ruby]] та деякими іншими мовами, в Python відсутня можливість модифікувати вбудовані класи, такі, як <code>int, str, float, list</code> та інші, що, однак, дозволяє Python споживати менше оперативної пам'яті і швидше працювати. Ще однією причиною введення такого обмеження є необхідність узгодження з модулями розширення. Багато модулів (з метою оптимізації швидкодії) перетворять Python-об'єкти елементарних типів до відповідних Сі-типів замість маніпуляцій з ними за допомогою Сі-API.

==== Глобальне блокування інтерпретатора (GIL) ====
[[GIL]] (Global Interpreter Lock)&nbsp;— проблема, притаманна [[CPython]], [[Stackless Python|Stackless]] та [[PyPy]], але відсутня в [[Jython]] та [[IronPython]]. При своїй роботі основний інтерпретатор Python постійно використовує велику кількість потіконебезпечних даних. В основному це словники, в яких зберігаються атрибути об'єктів. Для уникнення руйнування цих даних при спільній модифікації з різних [[нить|потоків]] перед початком виконання декількох інструкцій (за замовчуванням 100) потік інтерпретатора захоплює GIL, а після закінчення звільняє. Внаслідок цієї особливості в кожен момент часу може виконуватися тільки одна нить Python коду, навіть якщо на [[комп'ютер]]і є кілька [[процесор]]ів або процесорних ядер (GIL також звільняється на час виконання блокуючих операцій, таких як введення-виведення, зміни/перевірка стану синхронізуючих примітивів та інших&nbsp;— таким чином, якщо одна нить блокується, інші можуть виконуватися). Була зроблена спроба переходу до більш гранульованої синхронізації, проте через часті захоплення/звільнення блокувань ця реалізація виявилася занадто повільною<ref>{{Cite web |url=http://www.artima.com/weblogs/viewpost.jsp?thread=211200 |title=Python 3000 FAQ |accessdate=6 липня 2010 |archive-date=9 листопада 2020 |archive-url=https://web.archive.org/web/20201109015427/https://www.artima.com/weblogs/viewpost.jsp?thread=211200 }}</ref>. У найближчому майбутньому перехід від GIL до інших технік не передбачається, однак є python-safethread<ref name="google-safethread"> [http://code.google.com/p/python-safethread/python-safethread — Project Hosting on Google Code]</ref>&nbsp;— CPython без GIL і з деякими іншими змінами (за твердженнями його авторів, на однонитевих застосунках швидкість відповідає 60-65&nbsp;% від швидкості оригінальному CPython).

Ця проблема має два основних варіанти вирішення. Перший&nbsp;— відмова від спільного використання змінюваних даних. При цьому дані дублюються в нитях і необхідність забезпечення їхньої синхронізації (якщо така потрібна) лягає на програміста<ref>{{Cite web |url=http://perldoc.perl.org/perlthrtut.html |title=perlthrtut — perldoc.perl.org |accessdate=6 липня 2010 |archive-date=22 травня 2008 |archive-url=https://web.archive.org/web/20080522092213/http://perldoc.perl.org/perlthrtut.html }}</ref> Цей підхід веде до збільшення споживання оперативної пам'яті (однак не настільки сильно, як при використанні [[процес (програмування)|процесів]]).

Другий підхід&nbsp;— забезпечення більш гранульованої синхронізації&nbsp;— для окремих структур даних. У цьому випадку падає продуктивність внаслідок збільшення числа звільнень/захоплень блокувань.

Якщо необхідно паралельне виконання декількох нитей Python-коду, то можна скористатися процесами, наприклад, модулем processing<ref>{{Cite web |url=http://pypi.python.org/pypi/processing |title=Python Package Index: processing 0.52 |accessdate=6 липня 2010 |archive-date=13 жовтня 2007 |archive-url=https://web.archive.org/web/20071013121839/http://pypi.python.org/pypi/processing/ }}</ref>, який імітує семантику стандартного модуля threading, але використовує процеси замість нитей. Є безліч модулів, що спрощують написання паралельних та/або розподілених [[застосунок|застосунків]] на Python, таких як parallelpython<ref>{{Cite web |url=http://www.parallelpython.com/ |title=Parallel Python — Home |accessdate=6 липня 2010 |archive-date=28 травня 2010 |archive-url=https://web.archive.org/web/20100528112950/http://www.parallelpython.com/ }}</ref>, Pypar<ref>{{Cite web |url=http://datamining.anu.edu.au/~ole/pypar/ |title=Архівована копія |accessdate=6 липня 2010 |archiveurl=https://web.archive.org/web/20100106152936/http://datamining.anu.edu.au/~ole/pypar/ |archivedate=6 січня 2010 |deadurl=yes }}</ref>, pympi<ref>{{Cite web |url=http://pympi.sourceforge.net/ |title=pyMPI.sourceforge.net: Putting the py in MPI |accessdate=6 липня 2010 |archive-date=18 жовтня 2007 |archive-url=https://web.archive.org/web/20071018033650/http://pympi.sourceforge.net/ }}</ref> та інші. GIL звільняється при виконанні коду більшості розширень, наприклад, [[NumPy]]/[[SciPy]], дозволяючи на час розрахунків виконуватися іншому Python-ниті. Іншим рішенням може бути використання IronPython або Jython, позбавлених даного недоліку.

Крім того, існує спеціальна версія Python для віртуальної машини [[Java]]&nbsp;— [[Jython]], що дозволяє інтерпретатору виконуватися на будь-якій системі, що підтримує Java, класи Java можуть безпосередньо використовуватися з Python і навіть бути написаними на Python. Нещодавно почалася розробка системи, спрямованої на повнішу інтеграцію з платформою [[.NET]]&nbsp;— [[IronPython|Iron Python]].

[[Pyodide]] — це інтерпретатор Python, який працює у веббраузері завдяки використанню технології WebAssembly<ref>https://pyodide.org/</ref>. Pyodide є відкритим проєктом із вихідним кодом, доступним для спільноти розробників на [[GitHub]]<ref>https://github.com/pyodide/pyodide</ref>.

== Подальша розробка ==
[[Python Enhancement Proposal]] («PEP»)&nbsp;— це документ зі стандартизованим дизайном, що надає загальну інформацію про мову Python, включаючи нові пропозиції, описи та роз'яснення можливостей мови. PEP пропонуються як основне джерело для пропозиції нових можливостей і для роз'яснення вибору того або іншого дизайну для основних елементів мови. Видатні PEP рецензуються і коментуються [[BDFL]].

=== Графік і сумісність ===
Серії Python 2.x і Python 3.x протягом кількох випусків існували паралельно, при цьому серія 2.x використовувалася для забезпечення сумісності. PEP 3000 містить більше інформації про випуски.

Python 3.0 зворотно не сумісний з попередньою серією 2.x. Код Python 2.x швидше за все буде видавати помилки при виконанні в Python 3.0. Динамічна типізація Python, разом зі змінами декількох методів словників, робить механічний переклад з Python 2.x в Python 3.0 дуже складним. Однак, утиліта «2to3» здатна зробити більшість роботи з перекладу коду, вказуючи на підозрілі їй частини за допомогою коментарів і попереджень. PEP 3000 рекомендує тримати вихідний код для серії 2.x, і робити випуски для Python 3.x за допомогою «2to3». Отриманий код не слід редагувати, поки програма повинна бути працездатною в Python 2.x.

Розробники припинили підтримувати гілку Python 2.x у січні 2020 року. Остання випущена версія гілки Python 2.x: Python 2.7. Далі розробка ведеться лише у гілці Python 3.x<ref>{{cite web|url=https://endoflife.date/python|title=Python endoflife.date|publisher=endoflife.date|accessdate=18 вересня 2021|language=en|archive-date=18 вересня 2021|archive-url=https://web.archive.org/web/20210918162455/https://endoflife.date/python}}</ref>.

=== Можливості ===
Основні зміни, внесені до версії 3.0:<ref>{{Cite web |url=http://docs.python.org/dev/3.0/whatsnew/3.0.html |title=What's New In Python 3.0 — Python v3.0.1 documentation |accessdate=5 липня 2010 |archiveurl=https://web.archive.org/web/20081004052720/http://docs.python.org/dev/3.0/whatsnew/3.0.html |archivedate=4 жовтня 2008 |deadurl=yes }}</ref><ref>{{Cite web |url=http://docs.python.org/3.0/index.html |title=Overview — Python v3.0.1 documentation |accessdate=5 липня 2010 |archive-date=21 липня 2009 |archive-url=https://web.archive.org/web/20090721170811/http://docs.python.org/3.0/index.html }}</ref>
* Синтаксична можливість для анотації параметрів і результату функцій (наприклад, для передачі інформації про тип або [[документування]]).
* Повний перехід на [[unicode]] для рядків.
* Введення нового типу «незмінні байти» і типу «змінюваний буфер». Обидва необхідні для подання двійкових даних.
* Нова підсистема вводу-виводу (модуль <code>io</code>), що має окремі вигляди для бінарних і текстових даних.
* [[Абстрактний клас|Абстрактні класи]], [[Абстрактний метод|абстрактні методи]] (є вже в 2.6).
* Ієрархія типів для чисел.
* Вирази для словників і множин <code>{k: v for k, v in a_dict}</code> і <code>{el1, el2, el3}</code> (за аналогією зі списковими виразами).
* Зміни <code>print</code> з вбудованого виразу у вбудовану функцію. Це дозволить модулям робити зміни, підлаштовуючись під різне використання функції, а також спростить код. У Python 2.6 ця можливість активується введенням <code>from __future__ import print_function</code>.
* Функція <code>reduce</code> була переміщена з вбудованого простору в модуль <code>functools</code>. Проте  <code>map</code> або <code>filter</code> залишилися в вбудованому просторі.
* Видалення деяких застарілих можливостей, які підтримуються у гілці 2.x для сумісності, зокрема: класи старого стилю, цілочисельний поділ з обрізанням результату як поведінка за вмовчанням, рядкові винятки, неявний відносний імпорт, оператор <code>exec</code> тощо
* Реорганізація стандартної бібліотеки.
* Новий синтаксис для метакласів.
* Змінений синтаксис присвоєння. Стало можливим, наприклад, надання <code>(a, * rest, b) = range(5)</code>. З іншого боку, [[Параметр (програмування)|формальні параметри]] функцій на зразок <code>def foo (a, (b, c))</code> більше неприпустимі.

== Спеціалізовані підмножини/розширення Python ==
На основі Python було створено кілька спеціалізованих підмножин мови, в основному призначених для статичної компіляції в машинний код. Деякі з них:
* RPython<ref>{{Cite web |url=http://codespeak.net/pypy/dist/pypy/doc/coding-guide.html#restricted-python |title=PyPy (coding-guide) |accessdate=5 липня 2010 |archiveurl=https://web.archive.org/web/20070707005837/http://codespeak.net/pypy/dist/pypy/doc/coding-guide.html#restricted-python#restricted-python |archivedate=7 липня 2007 |deadurl=yes }}</ref>&nbsp;— створена в рамках проєкту [[PyPy]] значно обмежена реалізація Python без динамізму часу виконання та деяких інших можливостей. RPython код можна компілювати в багато інших мов/платформ&nbsp;— C, JavaScript, Lisp, .NET<ref>{{Cite web |url=http://codespeak.net/pypy/dist/pypy/doc/carbonpython.html |title=PyPy (carbonpython) |accessdate=5 липня 2010 |archiveurl=https://web.archive.org/web/20111012175212/http://codespeak.net/pypy/dist/pypy/doc/carbonpython.html |archivedate=12 жовтня 2011 |deadurl=yes }}</ref>, [[LLVM]]. На RPython написано інтерпретатор PyPy.
* Pyrex<ref name="pyrex" />&nbsp;— обмежена реалізація Python, але трохи менше, ніж RPython. PyReX розширено можливостями статичної типізації типами з мови С і дозволяє вільно змішувати типізований та не типізований код. Призначений для написання модулів розширень, компілюється в код на мові С.
* Cython<ref name=":0"/>&nbsp;— розширена версія Pyrex.
* pyastra<ref>{{Cite web |url=http://pyastra.sourceforge.net/ |title=Pyastra: python assembler translator |accessdate=12 травня 2022 |archive-date=9 листопада 2020 |archive-url=https://web.archive.org/web/20201109025501/http://pyastra.sourceforge.net/ }}</ref>&nbsp;— компілятор Python коду в асемблер для [[PIC]] архітектури.
* Shed Skin<ref name="shed-skin-blog" />&nbsp;— призначений для компіляції неявно статично типізованого Python коду в оптимізований код на мові [[C++]], проєкт далекий від завершення.
* [[PyScript]]&nbsp;— це [[фронтенд]]-[[фреймворк]]<ref>{{cite web|url=https://www.infoworld.com/article/3661628/get-started-with-pyscript-the-in-browser-python-by-anaconda.html |title=Intro to PyScript: Run Python in your web browser |work= InfoWorld |author=Serdar Yegulalp  |date= JUN 15, 2022 |time=3:00 AM PDT |accessdate=2022-07-26}}</ref> для створення програм на Python, вбудованих у [[HTML]]-код, для виконання в [[браузер]]і. Дозволяє імпортувати більшість модулів Python.

== Застосування ==
[[Файл:Python Powered.png|thumb|Python Powered]]
Python&nbsp;— стабільна та поширена мова. Вона використовується в багатьох проєктах та в різних якостях: як основна мова програмування або для створення розширень та інтеграції додатків. На Python реалізована велика кількість проєктів, також вона активно використовується для створення прототипів майбутніх програм.

Python використовується в багатьох великих компаніях<ref>{{Cite web |url=http://www.python.org/about/success/usa |title=Python Success Stories |accessdate=5 липня 2010 |archive-date=18 червня 2010 |archive-url=https://web.archive.org/web/20100618234049/http://python.org/about/success/usa/ }}</ref>.
